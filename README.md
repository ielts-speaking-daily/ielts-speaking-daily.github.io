# IELTS 每日口语：公开静态题库与 dot 通话辅导

本项目把完整定制口语资料放在 GitHub Pages：网页用于查题、安排每日练习、记录进度及文字反馈；dot 可直接读取公开 HTML / JSON，用户在 dot 中通话练习。录音只留在本机。大陆 577 题、海外 73 题，共 650 条中英参考答案；首轮 2026-10-09 至 2026-11-07，26 个新题日、4 个复习日，保留原计划。

本仓库是纯静态实现，不包含 D1、R2、MCP 后端、云端录音评测或网页内 dot 通话接口。旧 Sites 网站的服务、数据和推送不会自动成为 GitHub Pages 的功能。历史导入的 `viewed` 事件仍仅表示浏览，不能计为实际开口。

计划发布入口为 <https://ielts-speaking-daily.github.io/>，是否已生效以 GitHub Pages 部署结果为准；本说明本身不代表已上线。dot 的静态阅读入口是 `/dot/`，可直接点击 Day 01–30 和全部 Part / 海外题库，无需运行 JavaScript。

## 公开内容与访问权限

用户已授权完整定制题库、已确认背景及文字练习记录公开。任何人均可读取 `docs/` 下的 HTML、JSON 及已发布资料；这不是私人账号网站。录音不上传 GitHub，也不要把密钥、访问令牌、私人联系方式或未经授权的第三人信息写入仓库。

访客不能通过本网站写公共数据库。真正的修改权限是 GitHub 仓库的提交权限。dot 能阅读公开网址不等于已连接 GitHub，更不等于有写权限；需要使用用户明确授权的 GitHub 工具或由用户提交文件。公开仓库历史也可能保留曾提交的文字，普通后续编辑不会自动清除 Git 历史。

## 本机启动与检查

需要 Python 3；更新静态阅读页另需 Node.js。无需 npm 依赖或 API 密钥。

```powershell
# 在本仓库根目录执行；不要直接用 file:// 打开需要 fetch 的主页面
python -m http.server 8000 --directory docs
```

浏览 <http://localhost:8000/>；dot 静态页是 <http://localhost:8000/dot/>。dot 的云端环境通常不能访问用户电脑上的 localhost，给 dot 使用发布后的 HTTPS 地址。

改过题库、日程或人设后执行：

```powershell
node scripts/build-dot.mjs
```

脚本会检查 30 天的唯一题号、大陆首次分配完整性及元数据数量，失败时不会把缺题当作完整结果。生成页保留原题换行和完整 cue card，动态数据全部按 HTML 文本转义。若只追加 `records.json`，无需重建题目页：dot 应每次重新读取该文件。

## 发布到 GitHub Pages

1. 将本仓库文件推送到 `ielts-speaking-daily/ielts-speaking-daily.github.io` 的 `main` 分支。
2. 在 GitHub 仓库 **Settings → Pages → Build and deployment** 中选择 **Deploy from a branch**，分支 `main`、目录 `/docs`，保存。
3. 等待 Pages 部署完成，再打开 HTTPS 地址并检查 `/dot/`、`/data/records.json`、iPhone 布局及浏览器录音权限。
4. 后续提交仍需等待新版本发布。看到旧记录时先核对远端文件和部署状态，再刷新；不能仅因本机已保存便显示云端已同步。

`docs/.nojekyll` 保持存在。此处是发布步骤，不表示上述设置已替用户完成。

## 修改数据与追加记录

- 修改参考答案时保留稳定 QB ID；真实人设的修改只依据用户确认。源文待核及候选标记不能因为生成网页或完成朗读而自动删除。
- 参考稿有实质变化时增加题目的 `version`，原始稿通过 Git 历史或单独版本档案保留。不要复用旧题号代表新问题。
- `records.json` 使用 `schemaVersion: 1`，保留 `events`、`entries`、`reviewSessions` 三个数组；记录字段说明见 [dot 使用说明](docs/dot-instructions.md)。
- 新练习、反馈或修订创建全新 ID。修订文字记录用 `revisionOf` 指向旧 entry，旧版不覆盖；`createdAt` 是创建时间，未知练习日期的 `practiceDate` 必须为 `null`。
- 浏览记录不能冒充出声记录，朗读不能计成自主回答。助手反馈不能写入用户原话 `transcript`；候选故事需要单独明确确认。

浏览器新增记录先留在该设备的 localStorage。网页导出 `records.json` 后，先取得 GitHub 上的最新版本，按以下规则合并，再替换 `docs/data/records.json` 并提交；也可授权 dot 使用 GitHub 工具完成同样的提交。纯静态网站不保存 GitHub 令牌、不自动提交。

**合并规则：** 分别按三个数组内的 `id` 合并；同 ID、同内容只保留一条；同 ID、不同内容整次拒绝，要求人工检查，不能静默采用“最后写入”。处理冲突时保留两份原文件，根据实际含义新建修订 ID，并通过 `revisionOf` 关联文字记录。合并后保留所有已有记录，更新 `updatedAt` 为这次合并的真实 UTC 时间。

**多人 / 多设备提交：** 提交前读取最新文件及当前 Git SHA；远端已变更就重新合并，不能拿旧导出覆盖新提交。纯 GitHub 版本冲突不得通过强推掩盖。dot 的“已保存到网站”只能在工具返回成功提交、且 Pages 中已能读取相应记录后宣称；只生成 JSON 时应说“记录待提交”。

## 日常使用与提醒

每日先查看计划，再选择“朗读参考答案”或“自主回答”。全题库均可进入两种模式，但 30–40 分钟预算不保证每题都完整精批并复录。保留原计划的首轮覆盖目标，优先深练 1 题，有余量再加题；复习日处理欠课和真实薄弱点。

每日提醒采用网站提供的 ICS 日历文件，由用户主动导入日历；时间为 `Asia/Shanghai` 每日 20:00。日历通知取决于设备权限与用户日历设置。GitHub Pages 本身不运行定时任务或发送云推送；旧站任务如需停止，应在原服务中独立停用，导入前留意重复提醒。

## 能力限制

- dot 通话发生在支持 dot 的应用中。网站不嵌入 dot、不自动发起通话，也不保证 dot 能自动导出通话原音或逐字转写。
- 第一版以通话教学及文字归档为主，没有自动发音评测引擎。取得文字不等于听到了原音；缺音频证据时不输出发音评分或真实流利度评分。
- 朗读反馈不能证明用户独立的词汇和语法能力。单题练习不能生成整场 IELTS Band；任何助手诊断都不是官方成绩。
- 公开记录发布后可由其他设备读取；未发布的本机数据不会自动跨设备同步。删除浏览器数据可能丢失未导出的记录；录音请自行下载保存。
- 服务工作线程或离线缓存不提供后台录音、云端提醒或 GitHub 写回。首次联网读取成功和后来离线可用应分别检查。
- 录音格式及后台行为取决于浏览器。手机锁屏、来电或切应用可能中断录音；不得把中断音频当成完整答题样本。
